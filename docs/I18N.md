# Internationalization

Built-in locale IDs are `zh_CN` (简体中文) and `en_US` (English). JSON resources use stable dotted
keys such as `app.title`, `page.project`, `export.dialog_title`, and
`calibration.linear.name`. Built-in English and Chinese resources are test-enforced to have exactly
the same key set.

The Translation Service owns the active locale and emits `locale_changed` for runtime GUI updates.
The selection is stored in application settings and restored at startup. Business logic, combo-box
data, Plugin references, Calibration JSON, and Project JSON always use stable semantic IDs rather
than localized display strings.

Theme uses separate stable IDs `light` and `dark`. It is switched at runtime and persisted under
QSettings `ui/theme`; it is not a locale, translation key, Project field, scientific setting, or
formal-export input. Runtime locale switching retranslates `Version 0.1.0` / `版本 0.1.0`,
`By CXYL` / `辰星引力开发`, the target-state theme button, plugin display names, and schema labels
without changing the active theme or any stable plugin/configuration ID.

The `Project` and `Thrust Analysis` workspaces and all Export/Plugin/Settings dialogs implement
`retranslate()`. Runtime
switching refreshes their labels and schema-field labels without replacing stable ComboBox data or
discarding entered Parser/Calibration values. Schema properties may provide `x-i18n-key`; their
plain `title` is the fallback for third-party plugins.

The Export dialog has an independent output-language selector. Chinese artifacts use `_ZH` and
English artifacts use `_EN`; CSV headers, JSON display metadata, TXT report labels, and PNG-rendered
text follow that selection. `motor.eng` is intentionally excluded because its interchange format
is locale-neutral. Project files persist the output locale as a stable `zh_CN` or `en_US` value.

Fallback order is:

```text
requested locale → en_US → supplied default → translation key
```

A missing file/key or formatting value does not crash the application. Every official and user
plugin may place `i18n/<locale>.json` beside `plugin.json`; bundles are discovered from the plugin
record's source directory and merged without requiring changes to application resources. Keys
should be namespaced by plugin ID. The bundled plugin zh/en key sets are test-enforced for parity.
